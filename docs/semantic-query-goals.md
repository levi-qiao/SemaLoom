# 通用查询与选择式澄清：派工提示词

状态：Q0–Q4 已实施并离线验收（契约 `semaloom/v0.1` SemanticQuery，ADR-0011）。2026-09-14。实况模型项见 Q4 NOT_RUN。本轮的任务入口；不重新执行旧 G1–G5 或已完成审计。架构依据见 [通用语义查询建议](semantic-query-design.md)，原有错误基线见 [审计修复](audit-fixes.md)。

## 用户期望与完成标准

有足够定义、已补全口径和成功执行证据时，直接给出明确结果、适用范围和表格证据。唯一指标已识别但年份/合计未说时，Chat 按本体默认作答并给出置信度，而不是先挡住用户。真正有多个口径或比较分母时，才发起选择式澄清。确定性指计算和结论可核验，不表示原始业务数据已被审计，也不把模型自报 confidence 当正确性证明。

- 先查本体、已确认上下文和有权限的数据，能自行确认的信息不重复问用户。
- 需澄清时一次优先问一个关键问题，通常提供 2–4 个有业务含义、互斥的候选；多个独立问题确实能减少往返时才合并。候选来自本体/真实对象/已支持口径，有简短说明；页面点选提交，并提供“其他”自由说明和“都不符合 / 暂不清楚”的出口。没有真实候选时仍可用“其他”补充，不编造候选数值。
- 选择后保存本轮决策并继续原问题，能够处理连续澄清。比如先选“申报营业收入”，再选年份，已选指标不能丢失。默认值或推荐选项不等于用户已提交。
- 用户选择只补全意图或授权采用某口径；不能把选择变成来源事实、把 NULL 当零、把规则未知变为通过。
- 故障、无数据、能力不支持、口径不明分别处理。可恢复故障给真实错误和重试入口，不把修复基础设施的问题推给用户选择。
- 业务选择默认只影响当前会话；可选记忆需要显式作用范围。永久修改本体仍走现有草稿/校验/发布，不随聊天选择自动改写业务定义。
- 新企业只增加本体与来源绑定；新问法通过通用筛选/分组/聚合/窗口/表达式组合。SQL 能完成的同源分析下推数据库。

示例交互：

> “你说的收入是哪种口径？”
> ○ 申报营业收入 — 申报表中的营业收入
> ○ 申报应纳税所得额 — 计算所得税采用的所得额
> ○ 都不符合 / 暂不清楚
>
> 这些示例只在本体确实包含相应定义时出现；其他企业使用其自身的定义，不能固化进 core 或 prompt。

## Q0 — 先跑通可复用方案，再固定契约

```text
目标：以可运行证据确定“通用语义查询 + 网页选择式澄清”的复用方案，交给 Q1–Q3 一份可一致实现的契约。

查询侧先验证 Wren 当前 Python 内嵌规划能力；Cube/MetricFlow 用于对照，SQLGlot/Ibis 是可能的底座，不默认同时引入。将财务模型和一个非财税的最小模型投影到候选引擎，实测分组聚合、合法关联、主体/总体作用域与精确小数。只读本地合成数据，记录生成 SQL 和失败边界。若 Wren 不适配，再根据具体原因试一个最有希望的替代，最终只选一条主实现。

交互侧先检查项目已安装 pi-agent-core/pi-ai 的工具与 hooks，再查 pi 官方选择/提问扩展和 RPC。证明候选在当前 headless Node + Python + Web 模式可用。coding-agent 的 ctx.ui.select 与 agent-core 不是同一 API；不得为使用一个终端选择框，额外启动带文件/命令权限的 coding agent。没有合适的完整插件时，复用官方 Agent 循环，只实现最小的网页澄清协议与持久化适配，记录原因。

固定契约至少覆盖：可组合 SemanticQuery、prepare 的 READY/NEEDS_INPUT/UNSUPPORTED/SOURCE_ERROR 等语义、结果/计划引用、选择题及提交接口、恢复会话所需信息、版本失效、证据表格。名称可按项目风格细化。明确选项 id、业务标签、说明、对应的类型化语义选择；客户端不提交可执行 SQL/权限或任意计划补丁。定义两份契约样例：直接计算；两轮选择后计算。

说明候选 SDK 哪些能力已实测、哪些未覆盖；将外部 AST、MDL、错误映射归到接入模块。现有本体作为唯一真源，MDL 自动生成。限定首版为同源 PostgreSQL，写清支持的算子清单、能力拒绝和迁移路径，避免范围无限扩张。

按文档所有权更新适用 ADR、语义契约、DESIGN/PLAN 的对应范围；公共输入先保留语义 ID 和类型值。仅在必要且有充分验证的情况下提出公共 semantic SQL 接口的替代决策，不先偷开 raw SQL 工具。

交付选型证据、依赖精确版本/许可证、契约版本/样例、Q1–Q3 文件边界和运行命令。完成标准是候选实际跑过且契约可供实现，不是只写一份推荐名单；本任务不宣称产品迁移完成。
```

## Q1 — 让同一套核心承接组合分析

```text
目标：按 Q0 选型与固定契约实现通用语义分析，使新增企业和新的分析组合主要改配置，不再为每题增加核心分支。

拥有 core/compiler/runtime/adapters 与对应测试；app/chat/harness 由 Q2 拥有。依据固定契约提供可独立调用的 prepare/execute 接口及能力声明，并交接给 Q2。公共类型仅由本任务实现，协议新增字段先更新共同契约。

统一表达业务字段、类型化过滤、时间范围/分组、多个指标、聚合前后筛选、排序、限定窗口与临时表达式。粒度、业务身份、可加性、合法 Link 与缺失政策从本体取得。SQL 库或选定引擎负责实际计划/生成，数据库负责同源集合运算，SemaLoom 拥有业务语义与证据；不要再建一个 SQL 优化器。

缺少影响结果的业务选择时 prepare 返回 Q0 规定的结构化问题与真实候选；已有明确定义时直接 READY。SOURCE_ERROR 与用户需要选择的信息分开。所有兼容旧请求归一到同一执行链，替换并删除旧逐对象总体计算；仍必须保留的非同源点查路径明确边界，不作为静默兜底。

完成度以行为验收：至少两个不同领域的纯配置；按年/月与业务维度分组；范围/AND/OR筛选；多指标和 Top N；占比/相对均值/严格同行比较。数千行合成数据证明数据库聚合实际下推，50只限明细分页，不限制总体。支持范围以 Q0 清单为准，未支持窗口明确拒绝。

用独立 SQL/Decimal 验证一对多/多事实关联、复合身份、相同金额不同对象、重复 grain、NULL/缺失/故障、零分母、负值、时点余额、精度边界；金额不能退化为 float。比较主体过滤不缩小统计分母。SQL参数化，可信范围应用到每个基础关系，输出行数限制不截断聚合输入。

返回结果、统计口径、实际来源 Mapping/表字段、版本与下钻引用；无同一快照时明确下钻重查的时间差异。完成迁移后列出实际删除路径及所有仍保留兼容入口的调用者。交付可运行接口、迁移和回归证明，不以编译成功代替业务结果正确。
```

## Q2 — 主动选择式澄清与恢复执行

```text
目标：让 Chat 在能确定时直接回答，在影响答案的信息不完整时主动给业务选择题，并在选择后可靠继续原问题。

拥有 app/chat、harness 与对应测试/依赖，复用 Q0 已实测的官方插件/SDK方案和 Q1 的公共契约。复用当前 pi 原生工具/hooks/生命周期，服务端是已确认语义和候选绑定的真源。候选或引擎不具备某能力时给明确状态，不把 LLM 自报“确定”当判据。

实现 prepare → NEEDS_INPUT → 持久化问题 → 用户选择 → 合并类型化决策 → 再 prepare → execute → answer。选项来自本体/真实对象及受支持策略，不靠模型自由编造。可由模型提出需要澄清的意图，但服务器必须验证候选、槽位和值。用户选择后的恢复使用原问题与已确认选择，不把“选第二个”当作独立新问题；支持两轮及以上补全。

问题至少绑定当前会话、用户、版本和问题修订；提交只接收可验证的选项标识。旧选项、重复提交、串会话、改版本、伪造候选必须可预测处理。等待用户时落库并释放本轮 Node/连接资源；不靠一个无限等待的模型/数据库进程保存状态。刷新、应用重启后能恢复待答问题；停止或暂不清楚不产生猜测答案。

已确认缺失政策等信息跨澄清轮次保留，但不扩大到其他年份/指标或永久配置。推荐项不自动提交。可直接查到的名称/字段/现有定义先发现，不让用户补技术信息；无法证实的源事实不能靠选项变成已证实。

收敛当前只支持固定问法的 intent 正则与旧 clarification 文本路径到同一状态流程；保留必要的类型、预算、版本和事实引用校验。Q1 支持的多指标/多年度问题不能再被旧单指标年检查拦截。文本数值必须来自执行结果，Rule UNKNOWN 不写成通过。

向 Q3 交付固定 schema、直接回答/一轮选择/两轮选择/错误恢复样例。离线 pi faux + 实际 Python/隔离持久化验证全过程，涵盖断线、重启、保存失败、重复选择、改选和非法选项；证明等待不泄漏进程。新交互不能只在 mock worker 中可用，须跑官方 Agent 的真实工具循环（可用离线模型）。
```

## Q3 — 用户能点选，证据能读懂

```text
目标：把 Q2 的选择式澄清做成系统内顺畅的 Chat 交互，并用表格解释确定结果。

Q2交互契约固定后执行。独占frontend及对应测试/依赖/构建产物；复用现有ChatPage/EvidenceCard和已有控件。按 Q0 的复用结论处理插件，不为了几个选择卡片引入第二套聊天框架或状态系统。

显示问题、简明原因与通常2–4个真实业务候选，每个候选有名称/必要口径说明。支持单选；只有独立可组合维度明确需要时才多选。提供都不符合/暂不清楚的出口。选中后一次提交，在等待期间禁用重复提交；不把默认高亮当已确认。页面发选项id，不发可执行计划/JSON片段。

提交后保留原问题和已选口径，必要时接下一道选择题；刷新恢复未答问题，已作废/改版本选项不能继续使用。错误保留上下文并支持重试；连接失败、无数据、暂不支持和待用户补充各有清晰状态。已有信息充分时直接显示结果，不增加每次计算确认页。

结果先给引擎数值与范围，再提供口径、统计数量/分母、来源表字段和按需明细表。不展示原始JSON作为主界面，不用JS浮点重算结果。用户能看到本轮选了什么及来源是否缺失/未复核。

浏览器完成输入问题→点选→第二轮点选→结果表→刷新恢复，并验证键盘、390/1280px、长候选文字、双击/重试/过期选择。开发期可用Q2的契约样例，交付前必须连真实隔离Python服务，不能仅以page.route mock通过作为完成。更新必要DESIGN内容，不改共享业务核心。
```

## Q4 — 独立验收与重复逻辑审计

```text
目标：在 Q1–Q3 集成后的同一基线上，证明“可确定即答、缺信息则选择补齐、配置跨企业复用”，并独立检查是否存在双套执行逻辑。

只新增独立测试/复现/报告，不改产品实现。先核对Q0–Q3基线/依赖、复用实测与删旧路径证据；安装第三方库不算复用成功，截图按钮存在不算全链路通过。

至少覆盖：明确问题不追问；含糊指标；缺年份；同名不同企业；行平均与企业平均；比较分母不明确；缺失处理；两轮选择；都不符合/暂不清楚；用户改选；刷新/进程重启；重复/伪造/过期选项；来源失败；保存失败；超限与实际不支持的操作。每例核对预期该答、该问或该报错，选择后计划与上下文是否一致。

独立SQL/Decimal对照数值、粒度、单位、分母与缺失；使用未出现在实现示例中的非财税领域，新增包/绑定后不改core即可运行。数千行验证全量聚合和证据分页分开，构造关联放大反例。不能只比较同一引擎的两条API。

离线通过后，若当前授权provider可用，集中最多12次真实问题、不自动重试；至少含直接回答、两轮澄清、比较、缺失和新领域。缺少配置则真实模型项NOT_RUN，不抄旧轮通过。分别报告确定性计算、AI意图、交互恢复、来源可靠性；错误正文+正确卡仍FAIL，不能合并成“100%准确率”。

沿调用图核查：旧analyze_population是否只做兼容翻译；有无新旧统计双实现、两套工具schema、平行的澄清状态机、重复规则求值、遗留关键词分支、未使用helper和无调用者兼容开关。指出重复点和实际调用者，不把合法协议适配/兼容翻译误判冗余，也不删除独立oracle。

报告PASS/FAIL/NOT_RUN、最小复现、责任任务和证据路径。发现FAIL交回主agent修复验证，未执行项保持未执行。清理自己的服务与临时文件，留下可复现测试和交接。
```

## 查找复用方案的官方起点

实施 agent 应核对当时版本与实际 API，再做最小运行验证；以下是入口，不代表插件已经验证能直接接入。

- [pi Agent core](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md)：项目当前使用 agent-core，优先复用其工具循环和原生 hooks。
