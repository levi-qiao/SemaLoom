# SemaLoom Studio — 产品与前端设计

环境说明：侧栏标识本地开发环境，具体数据范围以来源配置和 [样本说明](quickstart.md) 为准，不无条件显示“未连接真实业务数据”。导入业务样本与完全合成 fixture 必须区分；模拟工作流在来源标签与实体描述中明确标注。

状态：已实现的合成控制面基线。当前 Studio 维护**一份**可编辑语义模型：实体图/目录、检查器、物理来源追踪、结构化编辑、来源注册与验证；**保存即编译并激活**，查询与判断读取该生效版本。不提供独立的草稿/变更审核页。Studio 与后端部署在同一 Python 应用内，面向业务建模者与数据接入者。业务示例用于验证通用模型，不决定导航、组件或 core 的行业类型。

## 1. 产品方向

用户从实体出发，理解它与其他实体的关系，查看属性（含测量槽）、可选指标词条、规则和操作，再追踪具体属性由哪些数据库表或 API 提供。编辑并保存后，模型立即可供查询与判断。指标是查询面稳定入口，不是 Studio 里与实体并列的独立建模中心。

默认图谱呈现 **实体类型（ObjectType）与业务关系（Link）**。例如「采购订单 → 供应商」，节点代表业务定义；「订单 PO-001」是实例，只有显式查询并获得数据权限后才出现在实例预览。模型图、来源追踪和执行证据分别标注，避免把已配置关系误当成已存在业务事实。

视觉方向：安静、精确、适合长时间工作的企业工具。信息层级来自排版、留白、边界和选中状态。采用浅色中性底、深石墨文字和单一低饱和强调色；不用营销首屏、渐变背景、玻璃卡片、发光连线、聊天入口或装饰性大数字。

## 2. 信息架构

| 入口 | 主要任务 |
| --- | --- |
| 图谱 | ProcessOn 式画布（React Flow）：拖节点、锚点拉线、点选后在右侧栏编辑。细节到「实体」菜单。 |
| 实体 | 完整维护：属性与测量槽、可选指标词条、多表/多接口映射、判断、操作和描述；右侧支持结构化 Code / DSL 实时预览与编辑。 |
| 数据源 | 点卡片配置连接，查看自动读取的表结构。 |
| API 接口 | 独立管理层级：统一维护 OpenAPI / REST 接口清单、灵活鉴权（Bearer / API Key / Basic）、接口在线导入与连通性测试；供 Action 与数据源按需关联。 |
| 问答 | 用业务语言提问；读取当前已保存并生效的模型。 |

图谱只做主要维护；属性、测量槽、可选词条和列级映射等细项在「实体」页。一个实体可以对应多张表。判断用来根据已有数据得出一件事是否成立，供操作当前提。Mapping 试读与问答使用同一份已保存模型。声明的 Link 用于点查与关系说明；集合统计可沿基数 ONE 且同一 PostgreSQL 来源的关系按关联属性分组，界面不得暗示一对多或跨源 JOIN 已可用。

“来源—映射—本体”是可追踪的职责层级；实体关系图仍以实体为中心，不强制把所有实体放进三列流水线。本体层对应本项目的 ObjectType、Property、Metric、Link 与约束；图形本身不增加额外推理语义。

### 工作区网格与导航对齐规范

1. **工作区自适应栅格（Workspace Grid System）**：
   - **单列全宽自适应**：通过 `.workspace:has(> :only-child)` 与 `.workspace.full` 将网格列宽设为 `minmax(0, 1fr)`。确保 API 接口列表、未展开详情的数据源视图等单列页面在任意屏幕尺寸（包括 1440px、2K、4K 及 2366px 超宽屏）下自适应拉伸铺满，杜绝因旧版硬编码幽灵侧边栏（如 380px）引起的右侧大面积断裂空白。
   - **双列主从柔性栅格**：图谱检查器、实体列表与配置抽屉使用柔性比例（例如 `minmax(0, 1.15fr) minmax(420px, 480px); gap: 20px;`），主内容区吃满剩余空间，右侧抽屉保持 420–480px 的舒适阅读与编辑尺寸并独立纵向滚动，杜绝双向挤压与横向滚动条。

2. **全局侧栏导航对齐规范（Navigation Alignment）**：
   - **图标统一居中盒**：所有导航按钮图标包裹于 `22x22px` 的 `.nav-btn-icon` 容器中居中渲染，彻底平抑不同 SVG 路径构图外框（如 API 倾斜链路、图谱拓扑节点）引起的 1–2px 视觉中轴抖动，保证所有导航项图标与文字严格平齐对齐。
   - **纯净直立激活条**：激活态（`button.active`）通过伪元素 `::before` 提供垂直直立指示条（`top: 7px; bottom: 7px; width: 3.5px; border-radius: 0 2px 2px 0;`），杜绝圆角容器使用 `box-shadow: inset` 在边角产生弯折弯角的瑕疵。
   - **基准线与边距对齐**：左上角品牌 Mark（SL）与底部环境状态指示点统一采用 `10px` 左右内边距，与中间所有导航选项处于绝对平齐的垂直参考线上。

## 4. 实体图谱

### 节点和关系

实体节点使用紧凑圆点加下方名称，不在节点上堆属性表。选中后右侧检查器按“概况 / 来源 / 判断”分层展开，一次只打开一层。完整页把属性和来源放在同一张表。节点数量少时展示全图；变多时默认只显示焦点及其一跳邻居，再按需展开。画布自适应容器，支持平移、滚轮缩放和适应。

选中节点用强调色边框与浅色底表示，邻接边加深，非相关节点适度降低对比但仍可辨识。状态以图标和文字表达，颜色作辅助；“有 2 个问题”不与“未保存”合并成一个状态。

业务关系用实线、方向箭头、动词和两端基数。Link 的 ONE 表示源到目标至多一个（图上标 `N→1`），例如「每个订单对应一个供应商」；不得把 ONE 显示成一对一或 1:1。MANY 为源到目标可有多个（`N→N`）。边可选择并编辑 Link 名称、两端类型及业务身份绑定。拖出连线只打开关系表单；实体页提供等价表单入口。完成类型检查并保存才成为模型关系。节点移动只改变个人视图，不修改模型摘要或触发发布。

### 三种查看方式

| 视图 | 显示内容 | 切换规则 |
| --- | --- | --- |
| 实体关系（默认） | 实体和已声明 Link | 首次显示当前领域的有限子图；超过预算以“还有 N 个邻居”展开 |
| 规则依赖 | 所选 Rule 与输入属性/指标及所属实体 | 点击规则时局部替换或叠加；虚线明确标记“依赖” |
| 来源追踪 | 所选实体/属性 → Mapping → 来源资源 | 下方面板按层排列；数据库落到表/列，API 落到 operation/响应字段 |

三类连线有独立图例与标签；来源追踪箭头标记“由此提供”，不混用业务关系方向。定义追踪表示可能的来源；执行追踪必须选择具体 evaluation/request，显示本次实际来源和版本。

### 交互

- 单击节点联动检查器；单击属性定位来源；单击 Rule 高亮依赖；单击追踪中的来源跳转数据源详情，并保留返回上下文。
- 搜索支持名称、semantic ID；结果选择后聚焦节点并展开必要邻域。服务端只返回有权查看的结果及计数。
- 提供“展开一跳”“仅看相关”“回到全图”和定位历史。自动布局由明确按钮触发，后台刷新不移动用户正在查看的节点。
- 平移、缩放、适应视图、键盘选择与实体列表等价入口完整。关系编辑不能只依赖拖拽；表单可选择起点和终点。
- URL 保存实体、视图和版本引用；个人面板宽度、缩放及坐标是独立视图偏好，不进入语义 release。切换版本前处理未保存修改。

初始建议显示最多 60 个节点/100 条边，单次展开最多 20 个邻居，总画布上限初设 200 节点。服务端分页、去重、预算与当前权限共同限制返回；前端隐藏不是数据授权。实现阶段在固定设备上验证后确定最终预算。

## 5. 实体检查器与建模

检查器标题包含名称、semantic ID、定义版本。图谱检查器页签为“概况 / 来源 / 判断”；实体页页签为“概况 / 属性与来源 / 关系 / 判断 / 操作”。Action 和 Policy 不另开一级导航。图谱节点同时给出属性、操作与来源计数。

实体页各页签共用同一套左右分栏：左侧编辑，右侧预览或说明，避免概况、属性、关系各自一套排版。属性与来源合并为一张表：一行业务属性对应一张表列或一个接口字段。金额和数量是带单位与可加性的属性，在同一行对到物理字段；Studio 不再单列「指标」配置。合计、平均是提问时的运算，由引擎编译为 SQL，不在本体里穷举公式；本体只标明 FULL / SEMI / NONE。删除属性前列出引用影响。

数据表来源在右侧预览列清单和前几行样本（授权、限行），点列名绑定当前属性，点行填入试读键。同一实体的属性落到多张表或接口时，提示为每张表配置业务关联键，供后续按键拼接查询；当前切片只采集键，不在浏览器里写 JOIN SQL。

“编辑实体”进入保留上下文的编辑页：概况 → 属性与来源 → 关系。创建时显示名称（可中文）与稳定英文 semantic ID 分字段；新实体必须带类型化身份属性和 identityKeys。已有 ID 修改按迁移处理，不用重命名标签偷偷改 ID。URL 的 `view`/`entity`、图谱选中与检查器共用同一实体选择。删除实体前列出有权限的引用影响；存在引用时拒绝直接删除，提供处理引用的路径。属性行使用稳定编辑身份，修改属性 ID 不得重建行并抢走焦点。

Rule 编辑采用输入选择、类型化运算和输出定义的结构化表单。展示可读公式预览；前端不执行金额公式，不把任意代码输入作为编辑能力。实体页的判断、关系、操作与属性/来源一样，都可以添加、编辑和删除；判断用结构化输入与运算符，不提供会假装已有类型检查的表达式执行器。Policy 单独配置领域声明的适用维度与半开生效区间。规则可用合成输入预览；来源预览只验证有权限的 Mapping 输入。正式规则运行和执行证据经 POST /v0.1/query 与 /v0.1/claims/evaluate，读取当前已保存并生效的模型。

## 6. 一个实体，多种来源

实体本身没有唯一 `datasourceId` 或 `tableName`。实体的属性（含测量槽）、可选指标词条及关系身份可以由不同 Mapping 提供；一个目标也可以有多个经过声明的候选来源。

以“采购订单”为合成例：

| 业务目标 | 来源及资源 | 接入含义 |
| --- | --- | --- |
| 订单号、供应商业务键 | 采购库 `purchase_orders` | 业务身份与关系键提取 |
| 订单金额 | 采购库订单表金额列，经对象 Mapping 绑定 | 订单口径、CNY、精确 Decimal；词条只命名，不另写 Mapping |
| 已付金额 | 财务库 `order_payment_totals.paid_amount` | 另一事实表上的金额槽，经订单业务键绑定；该来源已提供精确粒度汇总，词条只命名 |
| 审批状态 | 审批 API `getOrderApproval`，`/data/status` | 同实体的另一属性来源，按订单业务键查询 |
| 可进入履约 | Rule 引用订单金额、已付金额、审批状态 | Runtime 组合规范化观测并计算 |

“订单金额”和“已付金额”不能因为都是金额就成为候选来源。相同目标、相同口径和粒度的多个 Mapping，必须声明适用范围与明确优先级；可选备用来源须经过等价性审核。UI 展示“候选 / 当前上下文选中 / 不适用 / 歧义”，不能简单列一个全局“主数据源”。来源错误时不能默认改用另一个口径。

属性与来源页使用矩阵：行是业务属性，列为来源 Mapping、资源、字段和业务键。多表时额外展示关联键。概览中的“3 个来源”按 source ID 去重，不等于 3 张表。

## 7. Mapping 编辑与数据源管理

### Mapping 编辑

Mapping 绑定在实体页的「属性与来源」完成，与属性定义同一张表。编辑区左右约各一半：左侧是来源卡片（表或接口）和属性矩阵，右侧用当前表的列和前几行样本做预览。点来源卡片切换表/接口；点列名绑定到当前属性，点行填入试读业务键。数据源连接成功后自动读取表/列或 OpenAPI 清单。样本行是授权后的限行窥视，不是业务 Query。一个实体可有多张表和多个接口，每张表需绑定实体业务键。

编辑顺序：选择目标定义 → 选择来源及资源 → 绑定业务身份 → 配置字段/响应抽取 → 类型与显式转换 → 范围、grain、基数和完整性 → 校验。新增物理绑定不修改业务实体定义。

数据库来源配置 schema、表/视图、列、参数化筛选与只读角色。API 来源配置注册服务、允许的 GET operation、请求参数绑定、响应指针、类型、分页/完整性和错误映射。界面按 adapter 的已支持 profile 显示字段；OpenAPI Mapping 不要求 table/column，只提供来源清单中的已授权 GET 操作。指标 Mapping 另配 valueColumn/valuePointer、grain 绑定、filters 与 Mapping.perspective。连接设置只存在来源 profile，不得写入 ObjectType/Metric/Link。试读绑定已保存模型 revision：未保存时禁用，保存后执行；数据库失败与接口失败使用不同文案，并保留当前编辑以便恢复。连接检查使用已保存配置，异步结果不得覆盖正在编辑的字段。

转换首版仅允许契约支持的声明式操作；数据库表达式及 HTTP 调用由 adapter 编译。前端结构检查帮助定位，Compiler 的完整检查是生效依据。校验面板按“结构 / 语义 / 环境”分组，问题点击后定位到具体字段。

### 数据源管理

列表列出来源名称、协议、当前环境、连接检查时间、元数据版本、验证状态及受影响 Mapping 数量。“连接可用”“模型兼容”“可激活”分别展示。

注册来源是管理员能力，可配置目标连接及凭证引用；它不同于业务查询入口。秘密字段只接受新值或引用，不回显旧值；不保存在浏览器持久存储或 URL。测试连接、元数据读取与 API 试调用全部经过后端受控 adapter，浏览器不直接访问数据库/业务 API。API 读取 profile 只允许经审核的无副作用 operation。

来源结构发生变化时，显示受影响属性、规则与 Mapping。样本预览默认关闭，显式点击后按数据权限、行数和体积预算获取；元数据可见不代表有样本权限。Mapping 目录提供针对当前已保存 Mapping 的只读试读：调用方只提交业务键与已声明 grain 绑定，由服务端按 Mapping 白名单访问来源。试读不是业务 Query，也不能执行 Action。连接未成功时仍可保存模型，但不能伪装成连接验证通过。

### 密度与组件约束

间距使用 4、8、12、16、24、32 px。表格行高默认 40 px，紧凑模式 32 px；输入与按钮高 32 px，触摸布局提升到 44 px。输入圆角 4 px，面板/节点 6 px，Dialog 8 px。只在浮层使用轻阴影；页面通过分隔线组织，不套多层卡片。

每个操作区域最多一个主按钮。建模页主操作是“新建实体”或“保存”；来源页是“保存连接”。行内次要操作使用轻量按钮或菜单；危险操作显示目标名称及影响，确认后仍由服务端授权。隐藏按钮只是交互反馈，权限以服务端为准。

图标统一 16 px 线性风格、相同线宽，并有可访问名称。动效限于 120–180 ms 的状态过渡；尊重减少动态效果设置；图谱不持续漂移、不自动播放连线粒子。

### 统一弹窗与模态体系 (Unified Modal System)

为避免前端在不同页面散落孤立且风格不一致的浮层特殊处理，全局所有模态交互必须统一收敛至标准 `Modal` 组件（`frontend/src/Modal.tsx`）：

1. **统一阶梯尺寸体系**：
   - `sm` (460px)：轻量警告、删除确认、简易参数输入。
   - `md` (600px)：中型表单、单接口鉴权配置、简单映射校验。
   - `lg` (760px)：复杂表单、OpenAPI / cURL 批量导入、多列物理字段绑定。
   - `xl` (960px)：深度审计、运行时完整证据卡（EvidenceModal）及长链路物理字段回溯。
2. **统一视觉与质感基线**：
   - **遮罩层**：统一采用柔和深色毛玻璃 `rgba(15, 23, 42, 0.48)` + `backdrop-filter: blur(4px)`，突出焦点。
   - **居中与进场**：视口绝对居中，具备微缩放/平移入场动效（120ms），固定最大高度 `88vh`。
   - **骨架三段式**：
     - **Header**：左侧为标题（Title）、副标题（Subtitle）与语义徽章（Badge）；右侧支持自定义操作插槽（HeaderExtra）并标配统一微交互关闭按钮。
     - **Body**：独立平滑纵向滚动，杜绝因内容溢出导致视口双滚动条。
     - **Footer**：底栏固定，弹性间距，主操作按键一律靠右并单次操作。
3. **可访问性与快捷交互**：
   - 严格遵循 WAI-ARIA 规范（`role="dialog"`, `aria-modal="true"`, `aria-labelledby`）。
   - 内置全局键盘 `Escape` 监听卸载，支持点击半透明遮罩背景安全关闭。

### 实体配置与内敛收拢规范 (Lean Ontology & Minimal Presentation)

1. **消除繁琐冗余**：实体配置右侧收起冗长的说明文本与散装解释卡，统一升级为结构化 Code / DSL (YAML/JSON) 编辑器（`EntityDslEditor.tsx`）。建模人员直接在单屏中完成对本体大 JSON/DML 的直观对照与修改。
2. **两层严格分离**：
   - **人机交互层（Answer Prose / 界面文本）**：使用克制典雅的业务表述，杜绝在用户可见文本中暴露机器内部状态（如 `无额外属性`、`PRESENT`、`SUCCEEDED`、`全量已授权` 等技术标记），数值按业务声明 `unit` 与精度自然收敛，消除冗余尾零。
   - **严谨审计层（Evidence Drawer / Modal）**：重型机器细节（数据源物理 ID、数据库表名与字段路径、API Operation、快照哈希与执行耗时）全面收拢进可折叠证据卡或统一模态弹窗，保持零幻觉与 100% 审计可信度，且不污染常规工作台视觉。
3. **消除 AI 玩具感 Emoji**：全局杜绝散落 Unicode Emoji（如 📥、⚠️、✓ 等 AI 味符号），所有操作图标一律使用统一线宽的 14px/16px 矢量 SVG 精准图标（`IconImport`, `IconCheck`, `IconAlert`, `IconClose`），状态标识使用标准业务文字徽章。
4. **危险操作区内敛化（Civilized Danger Zone）**：删除实体等破坏性操作采用安静纯白的独立卡片（`#ffffff` 背景 + `1px solid var(--border)`）与描边幽灵危险键（`btn-outline-danger`），杜绝全屏横跨的荧光粉红（`#fef2f2`）报警条，保证长时间沉浸工作的平稳视觉体验。

## 9. 状态与保存

编辑状态：未保存 / 已保存 / 冲突。页头只在有未保存修改、刚保存或冲突时显示简短状态，不展示 revision/digest。保存成功即表示查询与判断可使用该版本。

Studio 维护 PostgreSQL 中的一份模型文档，保存携带 `expectedRevision`；冲突返回 409，提供「用当前修改重试保存」和「放弃本地修改并载入」，不能静默覆盖。模型与来源表单都纳入未保存保护；保存响应不得清掉保存期间的后续修改。输入先在当前表单维护，显式保存后生效；离开时提示未保存内容。撤销仅作用于尚未保存的本地编辑。模型保存与来源注册走控制面管理协议；业务系统写入才进入 Action 生命周期。每个操作区域最多一个主按钮：建模页主操作是保存，来源页主操作是保存连接，试读与检查连接为次要操作。

保存流程：Compiler 检查 → 写入模型 revision → 发布并激活当前环境指针。不要求独立审核人或单独的「变更」页。viewer 不提供保存控件。业务 Action 的人工审批与模型保存无关。

本地文件与 Studio 使用同一规范化类型及 Compiler。导出保留精确依赖；浏览器不直接写 Git。图坐标与个人面板偏好不参与摘要。

空态给出具体入口，例如“此实体尚未配置来源映射”；加载使用区域骨架，不重置整个画布；失败保留上下文并解释重试条件；无权限不暴露隐藏对象名称、节点计数或关系端点。

## 11. PostgreSQL 元数据与外部来源

项目自身使用 PostgreSQL 存储模型 revision、不可变 release 摘要、环境指针、来源注册和 Action 执行状态。模型定义使用版本化 JSONB 文档；保存时写入并激活环境指针。运行时 Evidence 仍按当前合成实现保存引用，不把业务全量结果写入控制面。

图谱的定义节点与边从领域声明及引用索引投影生成，不另外维护一份可编辑的“图数据库真相”。浏览器坐标只是展示状态。业务实例默认仍在来源系统；样本与必要证据按授权及保留策略处理。

项目元数据由 PostgreSQL 直接持久化，跨库读取由同一 Python 进程按业务 Link 组合。外部业务数据库/API 与项目元数据库分开配置，即使都使用 PostgreSQL 也保持不同角色和访问范围。

同一实体多来源必须同时进入契约与执行验收：SQL 属性与 API 属性绑定到同一业务身份；API 返回错键、重复记录、非有限金额、超时或未完成分页时明确处理。SQL Mapping 的参数化不能替代 API profile 对认证、响应抽取、分页和完整性的声明。

## 12. 验收与实施顺序

T09 已验证图谱、实体/属性/Mapping/可选指标词条编辑和本地审核发布切片，但结构化 Rule、对象/字段权限、文件往返及完整视觉负载证据尚未联合闭合。以下表格是验收要求，不表示全部已通过。实际剩余项以 [能力清单](capabilities.md) 为准，生产身份与真实 pilot 另需对应证据。

| 场景 | 完成证据 |
| --- | --- |
| 订单 → 组织 / 供应商 | 点击节点与关系，检查器定位正确；列表可完成同样导航 |
| 点击订单金额或交付风险 | 分别追踪到数据库列或 API operation/响应字段；同实体多来源可见 |
| 同一目标增加冲突 Mapping | 校验指出歧义，定位字段并阻止激活；不随机显示“主来源” |
| 修改被规则引用的属性类型 | 显示规则影响和 Compiler 错误；保存失败则不生效 |
| 两人修改同一模型 | 冲突不覆盖，可重试或放弃本地修改 |
| 只读用户或权限撤销 | 后端拒绝未授权修改，图谱、搜索和样本无旁路泄露 |
| 构建后的界面 | 一个 Python 入口可访问深链接、刷新、保存及发布；没有 Node 运行依赖 |

视觉验证覆盖 1440×900、1280×800、小屏和 200% 缩放，长中文名称、长 ID、空图、错误与密集关系。键盘可完成选择、查看来源、编辑和诊断定位；普通文字对比度目标至少 4.5:1，必要非文字控件至少 3:1，焦点清晰可见。图谱单次最多呈现 60 个实体，更多实体明确引导到等价目录；同领域节点按三列换行，避免越出画布。

2026-09-11 的固定合成负载为 5 个实体、2 条关系，Chromium 1280×800 本地验收记录页面 navigation duration 18 ms、实体选择至检查器更新 88 ms，低于首版 1 s / 200 ms 交互预算。该记录只证明当前合成负载，不外推大规模容量。

导航增加“问答”，页面主体只有问题输入与发送主操作。支持新建对话、进度、停止、错误后保留输入、刷新恢复当前会话；切身份/离开页面会停止当前请求。未配置模型或无分析权限明确禁用发送，不以假回答替代。

AI 解读以安全 Markdown 展示，禁用 raw HTML 与外部图片自动加载；金额、观测状态、Rule truth、自动 checks 和来源信息由服务器证据卡展示。Rule 定义中的 claim 字符串不能被渲染成一次已执行的 Claim。新功能和 Node 生命周期见 [Chat Harness](chat-harness.md)，不修改原模型编辑契约。

确定性数值结果可以在正文与 Evidence 之间增加 `ResultPresentation`：Chat 应用层从已授权查询结果生成版本化、有节点/列/行上限的通用 presentation projection，前端校验后再生成本地 json-render spec，展示 KPI、柱状图、趋势图、指标下拉和表格切换。标量 `values` 显示 KPI；带 grain 的聚合 `values` 生成报告，绝不拿逐条 EvidenceTable 冒充聚合图表。模型按场景提出视图偏好；服务端根据时间轴、单位、粒度、缺失情况生成可用视图，用户可以切换。高密度、多维或混合单位保留表格，文字足够时可以省略组件；关系图只展示已声明关联，不强制树形层级。Evidence 列用 `role / valueType / unit` 描述审计数据语义，前端不得根据“名称”等文案、行业 ID 或值形状猜测图表语义。json-render 与 Recharts 延迟加载；图表只做视觉几何，显示值来自服务端字符串。无投影、非法投影或不支持的形态直接省略该层，EvidenceCard 仍是完整审计来源。模型不能提供 projection/spec、组件名、URL 或 action；本体 YAML 不增加展示配置。

## 集合统计、证据与图谱工具增补

Chat 证据使用表格展示对象、引擎值、状态、统计范围/数量、分子分母、实际来源活动及有权限的表/字段映射；默认不提供 JSON 阅读界面。物理字段是后端固定版本的诊断投影，与模型解读分开。图谱使用 ELK 统一规划实体卡片、直角折线和标签占位，标签在独立可点击覆盖层展示；画布工具栏提供就地新建、点击起终点连接、取消、整理与适应。定义变更由模型保存生效，不让坐标改变语义摘要。详见 [分析质量](analysis-quality.md)。


审计修订：图谱工具栏在图谱区域内单独占行，画布缩放不会把标签带到工具栏下；小屏有明确画布高度，初始化与容器尺寸变化后适应视图。指标常规编辑保留 aliases/population，别名与年度统计配置提供结构化控件。集合问答文字标为“引擎结果说明”，保留统计证据表；保存失败提示历史未保存，不能显示成功完成。

## 选择式澄清（Q0 契约，Q3 实现）

当 `prepare` 为 `NEEDS_INPUT` 时，问答页显示问题、简短原因和真实业务候选（名称 + 必要口径说明）。服务器按选项语义种类给出 `SELECT` 或 `CARDS`：年度、字典取值、规则和判断对象用原生下拉，其余需比较说明的口径用卡片；前端不按槽名或业务域硬编码，也不重复显示下拉和卡片。点选即提交，不必手打选项名称。另加“其他”（就地输入补充说明）和“都不符合 / 暂不清楚”。等待期间禁用重复提交。默认高亮不是已确认。提交后保留原问题与已选口径，可接下一轮。刷新恢复未答问题；过期或改版本选项不可再用。属性取值字典在实体「属性与来源」编辑。

唯一指标已识别时，Chat 仍须通过卡片补齐缺失的年度与统计方式，不计算或展示置信度。规则使用原有确定性结论。未要求明细时不按对象逐条展开。问的是指标名称而不是“是什么/有哪些”时，服务端直接作答或出选择题，不先让模型解释定义。Chat 复用引擎 `prepare` 的 `NEEDS_INPUT`，没有默认补齐旁路。

范围属性下拉只显示该指标确有非空观测的类型化候选；其他指标或空值行不能制造选项。标题、值类型和文案来自本体属性，不根据 `year` 等字段名猜测。显式输入未列出的合法值仍可执行并显示无数据结果。回答后的省略式追问沿用已确认指标与统计方式，只替换本轮明确改变的范围或条件；启用 Jev 不改变这条交互。

已确定结果先展示引擎数值与范围，再给口径、统计数量/分母、来源表字段和按需明细表。主界面不是原始 JSON，浏览器不用 JS 浮点重算金额。连接失败、无数据、暂不支持和待用户补充状态分开。不引入第二套聊天框架。交互 schema 见 [ADR-0011](adr/0011-semantic-query-planner.md)。

### 选择式分析主责复验

歧义指标、比较口径及同名主体按必要信息点选；缺失年份和统计方式同样需明确确认。推荐项/高亮不等于提交。来源故障显示可重试错误并保留当前选择，不能静默关闭选择卡。统计证据展示全部结果的指标、计算方式、粒度、值、单位及有权查看的表字段；旧冗余 JSON 对象不再重复放进定义表。入口示例使用通用业务问题，不固定财税词汇。三轮选择、刷新恢复与实际 HTTP/数据库路径见 [能力清单](capabilities.md)。

本体介绍标为“本体说明 · AI 解读，非数据查询结果”，提醒定义存在不保证实际记录/年份覆盖/来源可用。目录证据默认展开，以表格显示类型、名称与 ID、口径/单位、描述与完整字段定义；不向用户展示原始 JSON。数值计算仍显示引擎说明。

长回答完成后定位到正文开头；目录表限定高度并允许滚动，避免证据把正文挤出当前视野。Studio HTML 入口要求缓存重新验证，防止新版构建后导航仍显示旧画布。

图谱根据有效画布宽度切换横向/纵向分层，减轻检查器占用宽度后全图缩小导致的文字难读；提供缩放与适应工具查看细节。

尚不能定位业务范围的问题提供可输入的补充说明卡片，允许停止；提交后按原问题加补充说明继续。缺失数据不补零，非时间类别不显示趋势。状态色只提示具体判断结果，不标作笼统“正常/异常”。
