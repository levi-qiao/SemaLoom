# SemaLoom Studio — 产品与前端设计

环境说明：侧栏标识本地开发环境，具体数据范围以来源配置和 [样本说明](local-business-samples.md) 为准，不无条件显示“未连接真实业务数据”。导入业务样本与完全合成 fixture 必须区分；模拟工作流在来源标签与实体描述中明确标注。

状态：已实现的合成控制面基线。当前 Studio 包含实体图/目录、检查器、物理来源追踪、结构化草稿、来源注册与验证，以及校验、独立批准和发布闭环。Studio 与后端部署在同一 Python 应用内，面向业务建模者、数据接入者和发布审核者。业务示例用于验证通用模型，不决定导航、组件或 core 的行业类型。

## 1. 产品方向

用户从实体出发，理解它与其他实体的关系，查看属性、指标、规则和操作，再追踪具体属性由哪些数据库表或 API 提供。编辑之后，能知道改了什么、影响谁、哪里校验失败，以及何时生效。

默认图谱呈现 **实体类型（ObjectType）与业务关系（Link）**。例如「采购订单 → 供应商」，节点代表业务定义；「订单 PO-001」是实例，只有显式查询并获得数据权限后才出现在实例预览。模型图、来源追踪和执行证据分别标注，避免把已配置关系误当成已存在业务事实。

视觉方向：安静、精确、适合长时间工作的企业工具。信息层级来自排版、留白、边界和选中状态。采用浅色中性底、深石墨文字和单一低饱和强调色；不用营销首屏、渐变背景、玻璃卡片、发光连线、聊天入口或装饰性大数字。

## 2. 信息架构

| 入口 | 主要任务 |
| --- | --- |
| 图谱 | ProcessOn 式画布（React Flow）：拖节点、锚点拉线、点选后在右侧栏编辑。细节到「实体」菜单。 |
| 实体 | 完整维护：属性、指标、多表/多接口映射、判断、操作和描述。 |
| 数据源 | 点卡片配置连接，查看自动读取的表结构。 |
| 变更与发布 | 查看候选差异、校验、独立审核并激活当前环境；对照草稿 revision 与已生效 digest。 |

图谱只做主要维护；属性、指标和列级映射等细项在「实体」页。一个实体可以对应多张表。判断用来根据已有数据得出一件事是否成立，供操作当前提。指标 Mapping 的试读是草稿预览；已发布查询与判断使用环境激活版本，不读取未发布草稿。

“来源—映射—本体”是可追踪的职责层级；实体关系图仍以实体为中心，不强制把所有实体放进三列流水线。本体层对应本项目的 ObjectType、Property、Metric、Link 与约束；图形本身不增加额外推理语义。

## 4. 实体图谱

### 节点和关系

实体节点使用紧凑圆点加下方名称，不在节点上堆属性表。选中后右侧检查器按“概况 / 来源 / 判断”分层展开，一次只打开一层。完整页把属性和来源放在同一张表。节点数量少时展示全图；变多时默认只显示焦点及其一跳邻居，再按需展开。画布自适应容器，支持平移、滚轮缩放和适应。

选中节点用强调色边框与浅色底表示，邻接边加深，非相关节点适度降低对比但仍可辨识。状态以图标和文字表达，颜色作辅助；“有 2 个问题”不与“未保存”合并成一个状态。

业务关系用实线、方向箭头、动词和两端基数。Link 的 ONE 表示源到目标至多一个（图上标 `N→1`），例如「每个订单对应一个供应商」；不得把 ONE 显示成一对一或 1:1。MANY 为源到目标可有多个（`N→N`）。边可选择并编辑 Link 名称、两端类型及业务身份绑定。拖出连线只打开关系表单；实体页提供等价表单入口。完成类型检查并保存才成为模型关系。节点移动只改变个人视图，不修改模型摘要或触发发布。

### 三种查看方式

| 视图 | 显示内容 | 切换规则 |
| --- | --- | --- |
| 实体关系（默认） | 实体和已声明 Link | 首次显示当前领域的有限子图；超过预算以“还有 N 个邻居”展开 |
| 规则依赖 | 所选 Rule 与输入属性/指标及所属实体 | 点击规则时局部替换或叠加；虚线明确标记“依赖” |
| 来源追踪 | 所选实体/属性 → Mapping → 来源资源 | 下方面板按层排列；数据库落到表/列，API 落到 operation/响应字段 |

三类连线有独立图例与标签；来源追踪箭头标记“由此提供”，不混用业务关系方向。定义追踪表示可能的来源；执行追踪必须选择具体 evaluation/request，显示本次实际来源和版本。

### 交互

- 单击节点联动检查器；单击属性定位来源；单击 Rule 高亮依赖；单击追踪中的来源跳转数据源详情，并保留返回上下文。
- 搜索支持名称、semantic ID；结果选择后聚焦节点并展开必要邻域。服务端只返回有权查看的结果及计数。
- 提供“展开一跳”“仅看相关”“回到全图”和定位历史。自动布局由明确按钮触发，后台刷新不移动用户正在查看的节点。
- 平移、缩放、适应视图、键盘选择与实体列表等价入口完整。关系编辑不能只依赖拖拽；表单可选择起点和终点。
- URL 保存实体、视图和版本引用；个人面板宽度、缩放及坐标是独立视图偏好，不进入语义 release。切换版本前处理未保存修改。

初始建议显示最多 60 个节点/100 条边，单次展开最多 20 个邻居，总画布上限初设 200 节点。服务端分页、去重、预算与当前权限共同限制返回；前端隐藏不是数据授权。实现阶段在固定设备上验证后确定最终预算。

## 5. 实体检查器与建模

检查器标题包含名称、semantic ID、定义版本与草稿标识。图谱检查器页签为“概况 / 来源 / 判断”；实体页页签为“概况 / 属性与来源 / 关系 / 判断 / 操作”。Action 和 Policy 不另开一级导航。图谱节点同时给出属性、操作与来源计数。

实体页各页签共用同一套左右分栏：左侧编辑，右侧预览或说明，避免概况、属性、关系各自一套排版。属性与来源合并为一张表：一行业务属性对应一张表列或一个接口字段。金额和数量是带单位的属性，在同一行对到物理字段；Studio 不再单列「指标」配置。合计、平均是提问时的运算，由引擎编译为 SQL，不在本体里穷举公式。删除属性前列出引用影响。

数据表来源在右侧预览列清单和前几行样本（授权、限行），点列名绑定当前属性，点行填入试读键。同一实体的属性落到多张表或接口时，提示为每张表配置业务关联键，供后续按键拼接查询；当前切片只采集键，不在浏览器里写 JOIN SQL。

“编辑实体”进入保留上下文的编辑页：概况 → 属性与来源 → 关系。创建时显示名称（可中文）与稳定英文 semantic ID 分字段；新实体必须带类型化身份属性和 identityKeys。已有 ID 修改按迁移处理，不用重命名标签偷偷改 ID。URL 的 `view`/`entity`、图谱选中与检查器共用同一实体选择。删除实体前列出有权限的引用影响；存在引用时拒绝直接删除，提供处理引用的路径。属性行使用稳定编辑身份，修改属性 ID 不得重建行并抢走焦点。

Rule 编辑采用输入选择、类型化运算和输出定义的结构化表单。展示可读公式预览；前端不执行金额公式，不把任意代码输入作为编辑能力。当前实体页只保留判断说明与只读摘要；结构化 typed 输入/运算符编辑依赖 Compiler 的 M1 契约，未就绪时不提供会假装已有类型检查的表达式执行器。Policy 单独配置领域声明的适用维度与半开生效区间。规则草稿可用合成输入预览；来源预览只验证有权限的 Mapping 输入，不能将草稿当作已批准 release 执行业务请求。正式规则运行和执行证据固定已发布版本，经 POST /v0.1/query 与 /v0.1/claims/evaluate，与 Studio 试读明确区分。

## 6. 一个实体，多种来源

实体本身没有唯一 `datasourceId` 或 `tableName`。实体的属性、指标及关系身份可以由不同 Mapping 提供；一个目标也可以有多个经过声明的候选来源。

以“采购订单”为合成例：

| 业务目标 | 来源及资源 | 接入含义 |
| --- | --- | --- |
| 订单号、供应商业务键 | 采购库 `purchase_orders` | 业务身份与关系键提取 |
| 订单金额 | 采购库订单表金额列，经对象 Mapping 绑定 | 订单口径、CNY、精确 Decimal；词条只命名，不另写 Mapping |
| 已付金额 | 财务库 `order_payment_totals.paid_amount` | 独立指标，通过订单业务键绑定；该来源已提供精确粒度汇总 |
| 审批状态 | 审批 API `getOrderApproval`，`/data/status` | 同实体的另一属性来源，按订单业务键查询 |
| 可进入履约 | Rule 引用订单金额、已付金额、审批状态 | Runtime 组合规范化观测并计算 |

“订单金额”和“已付金额”不能因为都是金额就成为候选来源。相同目标、相同口径和粒度的多个 Mapping，必须声明适用范围与明确优先级；可选备用来源须经过等价性审核。UI 展示“候选 / 当前上下文选中 / 不适用 / 歧义”，不能简单列一个全局“主数据源”。来源错误时不能默认改用另一个口径。

属性与来源页使用矩阵：行是业务属性，列为来源 Mapping、资源、字段和业务键。多表时额外展示关联键。概览中的“3 个来源”按 source ID 去重，不等于 3 张表。

## 7. Mapping 编辑与数据源管理

### Mapping 编辑

Mapping 绑定在实体页的「属性与来源」完成，与属性定义同一张表。编辑区左右约各一半：左侧是来源卡片（表或接口）和属性矩阵，右侧用当前表的列和前几行样本做预览。点来源卡片切换表/接口；点列名绑定到当前属性，点行填入试读业务键。数据源连接成功后自动读取表/列或 OpenAPI 清单。样本行是授权后的限行窥视，不是业务 Query。一个实体可有多张表和多个接口，每张表需绑定实体业务键。

编辑顺序：选择目标定义 → 选择来源及资源 → 绑定业务身份 → 配置字段/响应抽取 → 类型与显式转换 → 范围、grain、基数和完整性 → 校验。新增物理绑定不修改业务实体定义。

数据库来源配置 schema、表/视图、列、参数化筛选与只读角色。API 来源配置注册服务、允许的 GET operation、请求参数绑定、响应指针、类型、分页/完整性和错误映射。界面按 adapter 的已支持 profile 显示字段；OpenAPI Mapping 不要求 table/column，只提供来源清单中的已授权 GET 操作。指标 Mapping 另配 valueColumn/valuePointer、grain 绑定、filters 与 Mapping.perspective。连接设置只存在来源 profile，不得写入 ObjectType/Metric/Link。试读绑定已保存草稿 revision：未保存时禁用，保存后执行，文案标明草稿预览；数据库失败与接口失败使用不同文案，并保留当前编辑以便恢复。连接检查使用已保存配置，异步结果不得覆盖正在编辑的字段。

转换首版仅允许契约支持的声明式操作；数据库表达式及 HTTP 调用由 adapter 编译。前端结构检查帮助定位，Compiler 的完整检查是生效依据。校验面板按“结构 / 语义 / 环境”分组，问题点击后定位到具体字段。

### 数据源管理

列表列出来源名称、协议、当前环境、连接检查时间、元数据版本、验证状态及受影响 Mapping 数量。“连接可用”“模型兼容”“可激活”分别展示。

注册来源是管理员能力，可配置目标连接及凭证引用；它不同于业务查询入口。秘密字段只接受新值或引用，不回显旧值；不保存在浏览器持久存储或 URL。测试连接、元数据读取与 API 试调用全部经过后端受控 adapter，浏览器不直接访问数据库/业务 API。API 读取 profile 只允许经审核的无副作用 operation。

来源结构发生变化时，显示受影响属性、规则与 Mapping，并使旧环境验证失效。样本预览默认关闭，显式点击后按数据权限、行数和体积预算获取；元数据可见不代表有样本权限。Mapping 目录提供针对当前草稿 Mapping 的只读试读：调用方只提交业务键与已声明 grain 绑定，由服务端按 Mapping 白名单访问来源。试读不是已批准 release 的业务 Query，也不能执行 Action。草稿连接未成功时仍可保存草稿，但不能伪装成环境验证通过。

### 颜色与字体

| Token | 值 | 用途 |

### 密度与组件约束

间距使用 4、8、12、16、24、32 px。表格行高默认 40 px，紧凑模式 32 px；输入与按钮高 32 px，触摸布局提升到 44 px。输入圆角 4 px，面板/节点 6 px，Dialog 8 px。只在浮层使用轻阴影；页面通过分隔线组织，不套多层卡片。

每个操作区域最多一个主按钮。建模页主操作是“新建实体”或“草稿保存”；来源页是“保存连接”；“校验候选 / 批准候选 / 发布到当前环境”只在变更页，并按当前身份只显示一个主按钮。行内次要操作使用轻量按钮或菜单；危险操作显示目标名称及影响，确认后仍由服务端授权。隐藏按钮只是交互反馈，权限以服务端为准。

图标统一 16 px 线性风格、相同线宽，并有可访问名称。动效限于 120–180 ms 的状态过渡；尊重减少动态效果设置；图谱不持续漂移、不自动播放连线粒子。

| `ResourceBrowser` | 协议专属资源树、元数据版本、过期状态 |
| `DefinitionTable` | 筛选、分页、列配置、行内问题定位；可作为图谱的等价入口 |
| `ValidationPanel` / `ChangeReview` | 诊断定位、字段级差异、影响关系及确切审核范围 |

基础按钮、输入、菜单、弹窗、Tabs、Tooltip 只维护一套。本项目的领域组件在基础组件上组合；不建设通用低代码页面引擎。

## 9. 状态、保存与发布

三条状态分别显示：编辑状态（未保存/保存中/已保存/冲突）、验证状态（未验证/失败/通过/过期）、发布状态（草稿/待审核/已批准/已发布）。草稿保存成功不能被显示成“已发布”或“已生效”。页头同时给出草稿 revision 与当前环境 activeDigest。

Studio 编辑 PostgreSQL 中的版本化草稿，保存携带 `expectedRevision`；冲突返回 409，提供「用当前修改重试保存」和「放弃本地修改并载入」，不能静默覆盖，也不能只提供重新载入。文档草稿与来源表单都纳入未保存保护；保存或验证响应不得清掉保存期间的后续修改。输入先在当前表单维护，显式保存草稿；离开或切换环境时提示未保存内容。撤销仅作用于尚未保存的本地编辑，不回滚发布。草稿保存、来源注册和模型发布走控制面管理协议；业务系统写入才进入 Action 生命周期。每个操作区域最多一个主按钮：建模页主操作是保存草稿，来源页主操作是保存连接，试读与检查连接为次要操作。

发布流程：草稿保存 → Compiler 检查 → 目标环境验证 → 审查字段差异与影响 → 独立审核人批准该次校验 → 发布者原子激活租户环境。校验/批准绑定 candidateDigest、草稿 revision 和来源配置；作者不能自批（INDEPENDENT_REVIEW_REQUIRED）。修改候选内容或所需来源配置后，旧校验/批准失效，界面不得继续显示“已批准”。已发布版本只读，通过新草稿演进。本地开发可用身份切换完成双人审核演示，凭证仍走同源会话 cookie，不写入 localStorage。业务 Action 的人工审批与模型发布审批是不同流程，不共用一个“批准”标记。viewer 不提供校验/批准/发布控件。

本地文件与 Studio 使用同一规范化类型及 Compiler。导入先生成草稿差异，导出保留精确依赖；浏览器不直接写 Git。发布来源可为受审核 Git commit 或可信 Studio 草稿 revision，审核证明均由服务端绑定内容摘要、身份及目标环境。图坐标与个人面板偏好不参与摘要。

空态给出具体入口，例如“此实体尚未配置来源映射”；加载使用区域骨架，不重置整个画布；失败保留上下文并解释重试条件；无权限不暴露隐藏对象名称、节点计数或关系端点。历史发布与草稿图必须有清晰标识，禁止把两版关系混合成一张无标记图。

## 11. PostgreSQL 元数据与外部来源

项目自身使用 PostgreSQL 存储草稿/revision、不可变 release、环境与来源注册、验证/审核记录和 Action 执行状态。模型定义使用版本化 JSONB 文档，候选摘要、租户、修订、权限归属与状态转换由关系约束和事务绑定；运行时 Evidence 仍按当前合成实现保存引用，不把业务全量结果写入控制面。

图谱的定义节点与边从领域声明及引用索引投影生成，不另外维护一份可编辑的“图数据库真相”。浏览器坐标只是展示状态。业务实例默认仍在来源系统；样本与必要证据按授权及保留策略处理。

项目元数据由 PostgreSQL 直接持久化，跨库读取由同一 Python 进程按业务 Link 组合。外部业务数据库/API 与项目元数据库分开配置，即使都使用 PostgreSQL 也保持不同角色和访问范围。

同一实体多来源必须同时进入契约与执行验收：SQL 属性与 API 属性绑定到同一业务身份；API 返回错键、重复记录、非有限金额、超时或未完成分页时明确处理。SQL Mapping 的参数化不能替代 API profile 对认证、响应抽取、分页和完整性的声明。

## 12. 验收与实施顺序

T09 已验证图谱、实体/属性/Mapping/Metric 编辑和本地审核发布切片，但结构化 Rule、对象/字段权限、文件往返及完整视觉负载证据尚未联合闭合。以下表格是验收要求，不表示全部已通过。实际剩余项以 [统一收口清单](maturity-closure.md) 为准，生产身份与真实 pilot 另需对应证据。

| 场景 | 完成证据 |
| --- | --- |
| 订单 → 组织 / 供应商 | 点击节点与关系，检查器定位正确；列表可完成同样导航 |
| 点击订单金额或交付风险 | 分别追踪到数据库列或 API operation/响应字段；同实体多来源可见 |
| 同一目标增加冲突 Mapping | 校验指出歧义，定位字段并阻止激活；不随机显示“主来源” |
| 修改被规则引用的属性类型 | 显示规则影响和 Compiler 错误；草稿保存与发布通过分开 |
| 两人修改同一草稿 / 校验后再次编辑 | 冲突不覆盖，旧验证和批准不可复用 |
| 只读用户或权限撤销 | 后端拒绝未授权修改，图谱、搜索和样本无旁路泄露 |
| 构建后的界面 | 一个 Python 入口可访问深链接、刷新、保存及发布；没有 Node 运行依赖 |

视觉验证覆盖 1440×900、1280×800、小屏和 200% 缩放，长中文名称、长 ID、空图、错误与密集关系。键盘可完成选择、查看来源、编辑和诊断定位；普通文字对比度目标至少 4.5:1，必要非文字控件至少 3:1，焦点清晰可见。图谱单次最多呈现 60 个实体，更多实体明确引导到等价目录；同领域节点按三列换行，避免越出画布。

2026-09-11 的固定合成负载为 5 个实体、2 条关系，Chromium 1280×800 本地验收记录页面 navigation duration 18 ms、实体选择至检查器更新 88 ms，低于首版 1 s / 200 ms 交互预算。该记录只证明当前合成负载，不外推大规模容量。

## 集合统计、证据与图谱工具增补

Chat 证据使用表格展示对象、引擎值、状态、统计范围/数量、分子分母、实际来源活动及有权限的表/字段映射；默认不提供 JSON 阅读界面。物理字段是后端固定版本的诊断投影，与模型解读分开。图谱使用 ELK 统一规划实体卡片、直角折线和标签占位，标签在独立可点击覆盖层展示；画布工具栏提供就地新建、点击起终点连接、取消、整理与适应。定义变更仍由现有草稿保存，不让坐标改变语义摘要。详见 [分析质量](analysis-quality.md)。


审计修订：图谱工具栏在图谱区域内单独占行，画布缩放不会把标签带到工具栏下；小屏有明确画布高度，初始化与容器尺寸变化后适应视图。指标常规编辑保留 aliases/population，别名与年度统计配置提供结构化控件。集合问答文字标为“引擎结果说明”，保留统计证据表；保存失败提示历史未保存，不能显示成功完成。

## 选择式澄清（Q0 契约，Q3 实现）

当 `prepare` 为 `NEEDS_INPUT` 时，问答页显示问题、简短原因和真实业务候选（名称 + 必要口径说明）。候选卡片直接点选提交，不必先选再确认，也不用手打选项名称。另加“其他”（卡片内输入补充说明）和“都不符合 / 暂不清楚”。等待期间禁用重复提交。默认高亮不是已确认。提交后保留原问题与已选口径，可接下一轮。刷新恢复未答问题；过期或改版本选项不可再用。

唯一指标已识别时，Chat 先按本体可加性与来源最新年度作答，并标注假设与置信度；规则检查只评分，不作为是否回答的门闩。未要求明细时不按对象逐条展开。问的是指标名称而不是“是什么/有哪些”时，服务端直接作答或出选择题，不先让模型解释定义。引擎 `prepare` 对缺字段仍返回 `NEEDS_INPUT`，与 Chat 默认补齐分开。

已确定结果先展示引擎数值与范围，再给口径、统计数量/分母、来源表字段和按需明细表。主界面不是原始 JSON，浏览器不用 JS 浮点重算金额。连接失败、无数据、暂不支持和待用户补充状态分开。不引入第二套聊天框架。交互 schema 见 [ADR-0011](adr/0011-semantic-query-planner.md)。

### 选择式分析主责复验

歧义指标、比较口径及同名主体按必要信息点选；年份和合计在唯一指标下可由系统默认并计入置信度。推荐项/高亮不等于提交。来源故障显示可重试错误并保留当前选择，不能静默关闭选择卡。统计证据展示全部结果的指标、计算方式、粒度、值、单位及有权查看的表字段；旧冗余 JSON 对象不再重复放进定义表。入口示例使用通用业务问题，不固定财税词汇。三轮选择、刷新恢复与实际 HTTP/数据库路径见 [收口报告](semantic-query-closure.md)。

本体介绍标为“本体说明 · AI 解读，非数据查询结果”，提醒定义存在不保证实际记录/年份覆盖/来源可用。目录证据默认展开，以表格显示类型、名称与 ID、口径/单位、描述与完整字段定义；不向用户展示原始 JSON。数值计算仍显示引擎说明。

长回答完成后定位到正文开头；目录表限定高度并允许滚动，避免证据把正文挤出当前视野。Studio HTML 入口要求缓存重新验证，防止新版构建后导航仍显示旧画布。

图谱根据有效画布宽度切换横向/纵向分层，减轻检查器占用宽度后全图缩小导致的文字难读；提供缩放与适应工具查看细节。
